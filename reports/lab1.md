## 实验内容

### 主要实现功能

1. **虚拟内存管理系统**
   - 实现了SV39页表机制
   - 支持虚拟地址到物理地址的转换
   - 实现了内存区域管理（MapArea）

2. **系统调用实现**
   - `sys_get_time`: 获取当前时间（适配虚拟内存）
   - `sys_trace`: 内存跟踪和调试功能
   - `sys_mmap`: 匿名内存映射
   - `sys_munmap`: 内存解映射

3. **页表管理**
   - 页表项（PTE）的创建和管理
   - 页表的映射和解映射操作
   - 支持不同的内存权限设置

### 核心数据结构

#### 页表项（PageTableEntry）
```rust
pub struct PageTableEntry {
    pub bits: usize,
}
```

页表项包含了物理页号和各种标志位，用于控制内存访问权限。

#### 内存集合（MemorySet）
```rust
pub struct MemorySet {
    page_table: PageTable,
    areas: Vec<MapArea>,
}
```

管理进程的虚拟内存空间，包含页表和内存区域列表。

#### 任务控制块（TaskControlBlock）
```rust
pub struct TaskControlBlock {
    pub task_status: TaskStatus,
    pub task_cx: TaskContext,
    pub memory_set: MemorySet,
    pub trap_cx_ppn: PhysPageNum,
    pub base_size: usize,
    pub heap_bottom: usize,
    pub program_brk: usize,
    pub syscall_count: [usize; 500],

```

### 系统调用实现细节

#### sys_get_time 实现
重写了`sys_get_time`系统调用以适配虚拟内存：
- 使用`current_user_token()`获取当前进程的页表token
- 通过`translated_refmut`函数将用户空间指针转换为内核可访问的引用
- 安全地向用户空间写入时间信息

#### sys_trace 实现
实现了内存跟踪功能，支持三种操作：
- `trace_request = 0`: 读取指定地址的字节
- `trace_request = 1`: 向指定地址写入字节
- `trace_request = 2`: 获取系统调用计数

#### mmap/munmap 实现
- **mmap (syscall 222)**: 实现匿名内存映射
  - 检查地址对齐（页边界对齐）
  - 验证权限参数的有效性
  - 检查内存区域重叠
  - 创建新的内存映射区域

- **munmap (syscall 215)**: 实现内存解映射
  - 检查地址对齐
  - 查找对应的内存区域
  - 解除页表映射并释放物理页面

### 错误处理

实现了完善的错误处理机制：
- 地址未对齐返回 -1
- 权限检查失败返回 -1
- 内存区域重叠返回 -1
- 无效的系统调用参数返回 -1

## 问答作业

### 1. SV39 页表页表项的组成

SV39 页表项（PTE）为64位，组成如下：

- **[63:54]**: 保留位，必须为0
- **[53:28]**: 物理页号（PPN[2]）
- **[27:19]**: 物理页号（PPN[1]）
- **[18:10]**: 物理页号（PPN[0]）
- **[9:8]**: 保留位，必须为0
- **[7]**: D位（Dirty）- 脏位，表示页面是否被写过
- **[6]**: A位（Accessed）- 访问位，表示页面是否被访问过
- **[5]**: G位（Global）- 全局位，用于TLB管理
- **[4]**: U位（User）- 用户位，表示用户态是否可访问
- **[3]**: X位（eXecutable）- 执行位，表示页面是否可执行
- **[2]**: W位（Writable）- 写位，表示页面是否可写
- **[1]**: R位（Readable）- 读位，表示页面是否可读
- **[0]**: V位（Valid）- 有效位，表示页表项是否有效

**标志位作用：**
- **V位**: 控制页表项是否有效，为0时访问会触发缺页异常
- **R/W/X位**: 控制页面的读/写/执行权限
- **U位**: 控制用户态程序是否可以访问该页面
- **G位**: 标记全局页面，在切换地址空间时不需要刷新TLB
- **A位**: 硬件自动设置，表示页面被访问过
- **D位**: 硬件自动设置，表示页面被写过

### 2. 缺页异常类型

可能由缺页导致的异常包括：

1. **Instruction Page Fault (异常码12)**: 取指令时页面无效或无执行权限
2. **Load Page Fault (异常码13)**: 读取数据时页面无效或无读权限
3. **Store/AMO Page Fault (异常码15)**: 写入数据时页面无效或无写权限

### 3. 缺页时重要寄存器的值

发生缺页时的重要寄存器：

- **sepc**: 保存触发异常的指令地址
- **scause**: 保存异常原因码（12/13/15）
- **stval**: 保存触发异常的虚拟地址
- **sstatus**: 保存处理器状态，包括特权级等信息
- **satp**: 保存当前页表的基地址和ASID

### 4. Lazy策略的好处

Lazy策略的优势：

1. **减少内存占用**: 只在实际需要时分配物理内存
2. **提高启动速度**: 程序启动时不需要立即加载所有代码段
3. **节省I/O开销**: 避免加载从未使用的代码和数据
4. **提高系统整体性能**: 减少不必要的内存分配和页表操作

### 5. 10G内存的SV39页表占用估算

对于10G连续内存页面：
- 10G = 10 × 1024³ 字节 ≈ 2.6 × 10⁶ 个4KB页面
- 三级页表结构，每级最多512个条目
- 估算需要：
  - 1个一级页表
  - 约5个二级页表
  - 约2600个三级页表
- 总计约2606个页表页面，占用约10MB内存

### 6. Lazy策略实现思路

**实现方式：**
1. mmap时只记录映射信息，不立即分配物理页面
2. 在VMA（Virtual Memory Area）中记录映射的虚拟地址范围和权限
3. 访问时触发缺页异常，在异常处理中分配物理页面并建立映射

**缺页处理：**
1. 检查缺页地址是否在有效的VMA范围内
2. 检查访问权限是否符合VMA的权限设置
3. 分配物理页面并建立页表映射
4. 返回用户程序继续执行

### 7. swap策略中的页面失效表现

在swap策略中，页面被换出到磁盘时：
- **V位清零**: 页表项的Valid位设为0，表示页面无效
- **保留信息**: 在PTE的其他位中保存磁盘位置信息
- **访问触发异常**: 后续访问会触发缺页异常，操作系统从磁盘换入页面

### 8. 单页表的页表切换

在单页表情况下：
- **进程切换时**: 通过写入satp寄存器切换页表
- **系统调用时**: 不需要切换页表，因为内核地址空间已映射在同一页表中
- **中断处理时**: 同样不需要切换页表

### 9. 单页表的权限控制

通过页表项的U位控制：
- **内核页面**: U位为0，只有内核态可访问
- **用户页面**: U位为1，用户态和内核态都可访问
- **硬件检查**: 处理器硬件自动检查当前特权级和U位

### 10. 单页表的优势

1. **切换开销小**: 系统调用和中断时无需切换页表
2. **TLB效率高**: 内核地址的TLB条目在用户态也有效
3. **实现简单**: 不需要维护两套页表
4. **内存开销小**: 每个进程只需要一个页表

### 11. 双页表的切换时机

**双页表实现下的切换时机：**
- 进入内核态时（系统调用、中断、异常）切换到内核页表
- 返回用户态时切换回用户页表

**单页表的切换时机：**
- 只在进程切换时切换页表
- 系统调用和中断处理时不需要切换
