实验报告

功能实现总结
本次实验主要实现了 rCore 操作系统的基础特权级机制和异常处理功能。通过实现 trap 处理机制，操作系统能够正确处理用户态和内核态之间的切换，支持系统调用和异常处理。实现了基本的上下文保存与恢复功能，确保在特权级切换过程中程序状态的完整性。同时通过三个 bad 测例验证了特权级保护机制的正确性，确保用户态程序无法执行特权指令或访问特权寄存器，从而保证了系统的安全性。

简答作业

U 态特权指令测试
正确进入 U 态后，程序使用 S 态特权指令或访问 S 态寄存器会报错。通过运行三个 bad 测例进行测试：

SBI 版本**: rustsbi-qemu （按照实验指导书下载的最新版）
测试平台: QEMU RISC-V 64（QEMU8版本）

测试结果

1. ch2b_bad_address.rs
测试内容: 尝试访问地址 0x0 (空指针解引用)
预期行为: 触发页面错误异常
实际行为: 程序会触发 Store/AMO page fault 异常，内核捕获异常并终止程序

2. ch2b_bad_instructions.rs
测试内容: 在用户态执行 `sret` 指令
预期行为: 触发非法指令异常
实际行为: 程序会触发 Illegal instruction 异常，因为 `sret` 是 S 态特权指令，用户态无权执行

3. ch2b_bad_register.rs
测试内容: 在用户态读取 `sstatus` 寄存器
预期行为: 触发非法指令异常
实际行为: 程序会触发 Illegal instruction 异常，因为 `sstatus` 是 S 态寄存器，用户态无权访问

这些测试证明了特权级保护机制的有效性：用户态程序无法执行特权指令或访问特权寄存器。

2. trap.S 深入分析
L40：__restore 入口时的 sp 值和使用情景
sp 的含义: 刚进入 `__restore` 时，`sp` 指向内核栈上的 `TrapContext` 结构体的起始地址。

两种使用情景:
1. 异常/中断返回: 从内核态返回用户态，恢复用户程序的执行现场
2. 任务切换: 切换到新任务时，恢复新任务的执行上下文

L43-L48：特殊寄存器处理
ld t0, 32*8(sp)    # 加载 sstatus
ld t1, 33*8(sp)    # 加载 sepc
ld t2, 2*8(sp)     # 加载用户栈指针
csrw sstatus, t0   # 恢复状态寄存器
csrw sepc, t1      # 恢复异常返回地址
csrw sscratch, t2  # 设置用户栈指针到 sscratch

寄存器意义:
sstatus: 控制处理器状态，包括特权级、中断使能等。恢复后确定返回到用户态
sepc: 异常返回地址，指向用户程序中断时的下一条指令
sscratch: 临时保存用户栈指针，用于特权级切换时的栈切换

L50-L56：跳过 x2 和 x4 的原因

ld x1, 1*8(sp)
ld x3, 3*8(sp)
.set n, 5
.rept 27
   LOAD_GP %n
   .set n, n+1
.endr

跳过原因:
x2 (sp): 栈指针寄存器，将在 L60 通过 `csrrw sp, sscratch, sp` 特殊处理
x4 (tp): 线程指针寄存器，用户程序通常不使用，无需恢复

L60：csrrw sp, sscratch, sp 执行后的寄存器状态

执行后状态:
sp: 指向用户栈，从 sscratch 中恢复的用户栈指针
sscratch: 指向内核栈，保存之前的内核栈指针

这条指令实现了栈的切换：从内核栈切换到用户栈。

__restore 中的状态切换指令

状态切换指令: `sret` (L61)

切换原因:
`sret` 指令会根据 `sstatus.SPP` 位确定返回的特权级
由于之前设置了 `sstatus`，使得 `SPP=0`（用户态）
`sret` 执行时会跳转到 `sepc` 指向的地址，并切换到用户态

L13：__alltraps 中的 csrrw sp, sscratch, sp

在 `__alltraps` 的 L13 执行 `csrrw sp, sscratch, sp` 后：

寄存器状态:
sp: 指向内核栈，从 sscratch 中获取
sscratch: 指向用户栈，保存之前的用户栈指针

这实现了从用户栈到内核栈的切换。

从 U 态进入 S 态的指令

触发指令: 不是单一指令，而是异常/中断事件

触发方式:
系统调用: `ecall` 指令
异常: 如页面错误、非法指令等
中断: 如时钟中断、外部中断等

当这些事件发生时，硬件自动：
1. 保存当前 PC 到 `sepc`
2. 设置 `sstatus.SPP` 为当前特权级
3. 切换到 S 态
4. 跳转到 `stvec` 指向的异常处理入口

总结

通过对 trap.S 的分析，我们可以看到 RISC-V 的特权级切换机制：
1. 硬件自动保存关键状态
2. 软件负责保存和恢复通用寄存器
3. 通过 `sscratch` 实现栈的切换
4. 通过 `sret` 实现特权级的返回

这种设计既保证了系统的安全性，又提供了高效的上下文切换机制。
